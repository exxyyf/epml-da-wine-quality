# Отчет по настройке и использованию MLflow для трекинга экспериментов

## Настройка выбранного инструмента

### Установка и базовая настройка MLflow

MLflow был выбран как основной инструмент трекинга экспериментов.

Установка:
```bash
pip install mlflow
```

### Настройка базы данных

В проекте используется MLflow Tracking Server с локальным хранилищем, адрес задавался в ДЗ №2:

Запуск сервера:
```bash
mlflow ui
```
### Аутентификация и доступ

В рамках учебного проекта используется локальный MLflow сервер без аутентификации.

Архитектура проекта позволяет без изменений кода перейти к MLflow + S3 или MLflow + PostgreSQL

## Проведение экспериментов

В проекте был созданы эксперименты:

- wine-quality-exp-baseline-models

- wine-quality-exp-tracking

- wine-quality-exp-1

Были проведены более 15 запусков с различными алгоритмами и гиперпараметрами

**Модели:**

- Logistic Regression (lr)

- Random Forest (rf)

- MLPClassifier (mlp)

Гиперпараметры задаются через улучшенный params.yaml, что позволяет легко масштабировать число экспериментов, запускать серии экспериментов, обеспечивать воспроизводимостью

### Логирование метрик, параметров и артефактов

В train.py реализовано логирование:

**Параметры:**
- имя модели

- путь к данным

- гиперпараметры модели

**Метрики:**

- accuracy

- precision

- recall

- f1

**Артефакты:**

- сериализованная модель (.pkl)

- MLflow model

- metrics.json

Реализовано с помощью:

mlflow.log_params(model_params)
mlflow.log_metric("f1", f1)
mlflow.log_artifact(model_path)

### Система сравнения экспериментов

Для анализа экспериментов реализована утилита compare_runs.py, которая:

- выбирает top-N запусков по метрике

- поддерживает фильтрацию по параметрам

- экспортирует результаты в CSV

Пример использования:

```bash
python compare_runs.py \
  --experiment wine-quality-exp-baseline-models \
  --metric f1 \
  --top-n 5
```

### Фильтрация и поиск экспериментов

Используется стандартный MLflow filter string:

--filter "params.model_name = 'rf'"

Это позволяет:

- сравнивать только определённые модели

- анализировать влияние гиперпараметров

- автоматизировать отбор лучших запусков

## Интеграция с кодом

MLflow логирование интегрировано напрямую в:

- train.py

- compare_runs.py

- fetch_model_versions.py

Все основные действия логируются как MLflow runs.

### Декораторы для автоматического логирования

В train.py реализован декоратор:

```python
@mlflow_run()
def train(...):
    ...
```

Он автоматически:

- создаёт MLflow run

- задаёт имя запуска на основе названия модели и названия функции (train) - с этим пришлось повозиться, в итоге реализовала с помощью доп. функции

- запускает эксперимент и логирование

### Контекстные менеджеры

Для управления экспериментами реализован контекстный менеджер:

```python
with mlflow_experiment("wine-quality-exp-1"):
    ...
```

### Утилиты для работы с экспериментами

Были реализованы следующие утилиты:

- compare_runs.py - сравнение запусков

- fetch_model_versions.py - анализ Model Registry, загрузка нужной версии модели

- mv_dashboard.py - визуальный dashboard для сравнения версий модели


### Управление версиями моделей

Модели регистрируются в MLflow Model Registry:

```
mlflow.sklearn.log_model(
    model,
    registered_model_name="wq-demo-mlp"
)
```

Поддерживаются:

- версии моделей

- стадии (например, train)


### Визуализация результатов

С помощью mv_dashboard.py реализован dashboard на Streamlit:

- таблица версий моделей

- графики метрик по версиям

- просмотр параметров моделей

Запуск:

```bash
streamlit run epml_da/modeling/mv_dashboard.py
```
